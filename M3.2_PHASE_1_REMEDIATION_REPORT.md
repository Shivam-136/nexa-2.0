## 2. DETAILED IMPLEMENTATION BREAKDOWN

### 2.1 Configuration Layer (`nexa-desktop/src/main/config.js`)
* **Actions:**
  1. Removed `STORAGE_SAVE_CREDENTIALS: 'nexa:storage-save-credentials'` from `IPC_CHANNELS`.
  2. Removed `STORAGE_CLEAR_CREDENTIALS: 'nexa:storage-clear-credentials'` from `IPC_CHANNELS`.
* **Result:** `IPC_CHANNELS` contains strictly safe read and window management channels. Zero credential mutation channels are defined.
* **Code State:**
  ```javascript
  const IPC_CHANNELS = Object.freeze({
    PING: 'nexa:ping',
    GET_APP_INFO: 'nexa:get-app-info',
    GET_SYSTEM_STATUS: 'nexa:get-system-status',
    WINDOW_MINIMIZE: 'nexa:window-minimize',
    WINDOW_MAXIMIZE: 'nexa:window-maximize',
    WINDOW_CLOSE: 'nexa:window-close',
    WINDOW_IS_MAXIMIZED: 'nexa:window-is-maximized',
    APP_QUIT: 'nexa:app-quit',
    STORAGE_GET_STATUS: 'nexa:storage-get-status',
    STORAGE_GET_DEVICE_INFO: 'nexa:storage-get-device-info',
  });
  ```

### 2.2 Preload Whitelist & Channels (`nexa-desktop/src/preload/channels.js`)
* **Actions:**
  1. Removed `'nexa:storage-save-credentials'` and `'nexa:storage-clear-credentials'` from `ALLOWED_INVOKE_CHANNELS`.
  2. Deleted `validateStorageSavePayload(payload)` function entirely (54 lines of code removed).
  3. Removed `validateStorageSavePayload` from `module.exports`.
* **Result:** `ALLOWED_INVOKE_CHANNELS` permits only `nexa:storage-get-status` and `nexa:storage-get-device-info` within the storage domain.

### 2.3 Preload Context Bridge (`nexa-desktop/src/preload/index.js`)
* **Actions:**
  1. Synchronized `ALLOWED_INVOKE_CHANNELS` in `src/preload/index.js` to omit both save and clear channels.
  2. Deleted `validateStorageSavePayload(payload)` from sandboxed preload context.
  3. Removed `saveCredentials` and `clearCredentials` from `nexaDesktopAPI.storage`.
  4. Preserved only safe read functions on `nexaDesktopAPI.storage`:
     * `getStatus()`: Returns encryption availability and paired boolean status.
     * `getDeviceInfo()`: Returns strictly redacted metadata (deviceToken is strictly omitted).
     * `onStatusChange()`: Subscribes to storage status change push notifications.
* **Result:** Calling `window.nexaDesktop.storage.saveCredentials` or `window.nexaDesktop.storage.clearCredentials` evaluates to `undefined`.

### 2.4 Main Process IPC Router (`nexa-desktop/src/main/ipc.js`)
* **Actions:**
  1. Deleted the `ipc.handle(IPC_CHANNELS.STORAGE_SAVE_CREDENTIALS, ...)` handler.
  2. Deleted the `ipc.handle(IPC_CHANNELS.STORAGE_CLEAR_CREDENTIALS, ...)` handler.
  3. Preserved safe read handlers: `STORAGE_GET_STATUS` and `STORAGE_GET_DEVICE_INFO`.
* **Result:** If an attacker attempts to invoke `'nexa:storage-save-credentials'` or `'nexa:storage-clear-credentials'` directly over IPC, Electron immediately rejects the call with an unhandled channel error (`No handler registered for '...'`).

### 2.5 Secure Storage Internal Hardening (`nexa-desktop/src/main/storage/secureStorage.js`)
* **Actions:**
  1. Retained `saveCredentials(rawPayload, { allowOverwrite = false } = {})` as an **internal Main Process method**.
  2. Guarded against silent credential overwriting:
     ```javascript
     if (this.hasCredentials() && !allowOverwrite) {
       const errMsg = 'NEXA_ERR_VAULT_ALREADY_EXISTS: Cannot overwrite active credentials without explicit authorization.';
       console.error(`[NEXA SecureStorage] ${errMsg}`);
       throw new Error(errMsg);
     }
     ```
  3. Retained `clearCredentials()` as an **internal Main Process method** for future authorized unpair operations (e.g., triggered by native dialogs or authenticated backend revoke commands in Milestone 3.3).
* **Guarantees Preserved:**
  * Windows DPAPI via Electron `safeStorage.encryptString()` and `decryptString()`.
  * Atomic file writes (`.tmp` write + `fs.renameSync` to `secure-vault.json`).
  * Fail-closed policy on unavailable DPAPI.
  * Corrupted vault quarantine (`.corrupt.<timestamp>`).
  * In-memory cache zeroization on shutdown (`clearMemoryCache()`).

## 5. STARTUP VERIFICATION TRANSPARENCY

In strict compliance with directive instructions, we report the exact behavior of `scripts/verify-startup.js`:
* When executed in environments where the subshell inherits `ELECTRON_RUN_AS_NODE=1` (common in VS Code or IDE subshells), Electron's binary runs as pure Node.js. In this mode, `require('electron')` resolves to the path string rather than the API, causing `app.whenReady()` to throw a `TypeError` and exit with code 1.
* When launched with a cleaned environment (`delete process.env.ELECTRON_RUN_AS_NODE`), pure `electron.exe` initializes and exits with code 0.
* **We do not claim startup verification passed under the contaminated subshell environment.** Full runtime test harness hardening remains scheduled for the Phase 2 test wrapper.
